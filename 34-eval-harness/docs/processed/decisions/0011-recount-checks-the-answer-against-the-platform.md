# 0011 Recount tasks check the agent's answer against the platform

- **Status:** Accepted, 19 Nov 2026. Amends [0005](0005-verifiers-never-read-the-answer.md) for recount tasks only.
- **Context:** On 17 Nov an agent that does nothing passed all 24 of our tasks, because every task only checked that nothing changed. For report agents (seat 31, seat 35) the answer is the work, so a check that never reads it cannot tell a working agent from no agent. The instructor agreed the recount plan for 30 Nov and gave the grader to Ranjani (18 Nov).
- **Decision:** A recount task asks a question with a list of record ids as the answer. The agent states it in its `AGENT_RESULT` line, under `answer`. Before the agent starts, the trial saves the rows a named rule needs (`eval_harness/rules.py`), and reads them again after. The grader passes only if the stated ids match the ids the rule picks from those rows. The truth still comes from the platform. The agent's words are checked, never trusted. A missing answer fails; a failed platform read is unevaluated.
- **Consequences:** Rules are written from each seat's written rule, never imported from its code. Ids written by hand into `suite.toml` are not used, because they go stale on live data. Recount runs alongside `no_writes_since_start`, so a right answer with changed data still fails. All other tasks are graded as before.
